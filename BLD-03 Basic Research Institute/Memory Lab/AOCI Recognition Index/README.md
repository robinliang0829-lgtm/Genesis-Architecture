# 长文本阅读理解引擎（Admit 层先行）

把「任意长文本 / 对话 / 导出记录」稳定变成 **AOCI 可复核认知** 的通用引擎。
不是聊天总结器，不是某个产品的专用导入器。

## 模块边界

```
Ingest → Segment → Author → Admit → Export → Ask
```

| 模块 | 职责 |
|---|---|
| Ingest | 文件/对话 → 统一文档模型（docId、来源类型、参与者、有序片段、原文哈希） |
| Segment | 有界切分 + 稳定坐标（sourceId + offset + length，可拼回、不乱序） |
| Author | 模型读片段、起草 Entry / 主张 |
| **Admit** | **本地校验 + AOCI 提交 + 退回修复（本目录核心）** |
| Export | 标准阅读理解包（AOCI 资产 + 片段索引 + 主张↔原文映射） |
| Ask | 基于包做有据问答，答案带证据定位 |

Admit 和 Export 必须最稳、最通用。下游产品（Soul Forge、笔记、检索、问答）只接这两层，不各自魔改入账。

## 核心设计决策：长文本如何映射到 AOCI

AOCI-CODE 的受管对象是「文件」（`code:<path>`），一条 Entry 描述一个对象。
因此长文本走「**段文件物化**」路线：

1. Segment 把文档切成有界段，每段落成一个段文件 `corpus/<docId>/seg-<k>.txt`
   （文件头带 sourceId + offset + length + 原文 sha256，锚点天然可复现）。
2. AOCI 把每个段文件当一个 `code` 对象，收下一条 FRAS Entry。
3. 主张 = Entry 的 F/S；锚点 = 段文件头里的坐标，能按坐标在原文精确复现。
4. Export 包 = AOCI 已收下的条目 + 段索引 + 主张↔原文映射。

## Admit 契约

- 输入：候选 `Entry[]`（每条可带 `anchor = {sourceId, offset, length}`）+ 原文片段映射
- 输出：`accepted / rejected` + 机器可读原因

校验顺序（全部**本地**完成，先于 AOCI 提交，避免盲目烧机器拒绝）：

1. **结构**：`object[tag]: F:.. | R:.. | A:.. | S:..`
2. **标签**：A/B 必须在 Meta 词典，C ∈ 1..9，E ∈ {L,M,S,T}；不造字母
3. **长度**：F ≤ 160 runes，R ≤ 360 runes / 8 项，A ≤ 400 runes / 6 项
4. **S 配额**：runes 按 C 档（C9-8≤600 / C7-4≤200 / C3-1≤50）+ token 上限（1 token=UTF-8 字节/3）
5. **锚点**：每条主张必须带坐标，且能按坐标在原文精确复现（缺引用 = 拒绝）

退回策略（「不盲目重烧」的核心）：

- 结构 / 标签 / 预算问题 → **本地修**（machine-fixable），不重烧模型
- 语义问题 → 有限次（默认 1 次）模型重写，仍失败则明确 rejected
- 绝不在失败后静默重试

## 验收口径（通用、可测）

- 小对话（几 KB）、中等 Markdown（几百 KB）、超长导出（10MB+）三档都要过。
- 全部分段可追溯到原文；任意抽主张，坐标核对原文 100% 命中。
- 人为制造超长 S / 非法 tag / 缺引用，系统本地修或明确拒绝。
- 重启后复用已入账结果，不重复付费生成。
